# Pull Request 指南

## 创建 PR

### 标签

在使用 AI 辅助创建 PR 时，始终添加 **"AI-Made"** 标签。

### PR 标题

在开头包含问题编号：

```
RI-123 Add user profile editing
#456 Fix memory leak in connection pool
```

### PR 描述模板

```markdown
# What

描述变更内容。

# Testing

描述如何测试变更。

---

Closes #RI-123
```

**PR 描述指南：**

- **保持简洁** - 避免冗长的描述
- **专注于高级变更** - 不要在 #What 部分列出每个代码变更
- **简短扼要** - diff 显示详细信息；在高层次描述"为什么"和"什么"
- **技术决策** - 仅在相关时提及重要的架构或设计决策

## 审查流程

### 作为 PR 作者

- **回应所有评论** - 处理每一条反馈
- **不要对反馈个人化** - 审查提高代码质量
- **根据反馈更新代码** - 进行请求的变更
- **将对话标记为已解决** - 处理反馈后
- **保持 PR 最新** - 定期在 main 上变基

### 作为 PR 审查者

- **建设性和尊重** - 专注于改进
- **关注逻辑，而非风格** - 由 linter 处理格式化
- **检查**：
  - 逻辑错误和边缘情况
  - 性能问题
  - 安全问题
  - 测试覆盖率
  - 缺失的文档
  - 架构问题

### 审查检查清单

- [ ] 代码遵循项目模式
- [ ] 测试全面
- [ ] 没有 console.log 或调试代码
- [ ] TypeScript 类型正确
- [ ] 错误处理充分
- [ ] 文档已更新
- [ ] 没有安全漏洞
- [ ] 性能可接受
