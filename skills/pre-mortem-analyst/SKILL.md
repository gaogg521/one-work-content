# 事前分析（Pre-Mortem）

## 为什么 Pre-Mortem > 风险评估

**风险评估：** "什么可能出错？" → 乐观偏见过滤答案
**事前分析：** "六个月后的今天，项目已经失败了。为什么？" → 释放诚实的分析

研究：Pre-mortems 将问题识别率提高 30%。

## 过程

1. **设定场景：** "今天是 [日期]。这个项目已经完全失败了。"
2. **头脑风暴原因：** 列出 10+ 个失败原因（不筛选）
3. **分类：** 人员、流程、技术、外部
4. **评分：** 可能性 × 影响 (高/中/低)
5. **预防：** 前 3 项获得具体的缓解措施
6. **监控：** 定义早期预警信号

## 输出格式

```
项目: [名称]
失败场景: "今天是 [日期]。[项目] 已经完全失败了。"

失败原因:

👥 人员: [原因] - 可能性×影响: 高/高 | 预防措施: [x] | 预警信号: [y]
⚙️ 流程: [原因] - 可能性×影响: 中/高 | 预防措施: [x] | 预警信号: [y]
💻 技术: [原因] - 可能性×影响: 低/高 | 预防措施: [x] | 预警信号: [y]
🌍 外部: [原因] - 可能性×影响: 中/中 | 预防措施: [x] | 预警信号: [y]

前 3 项优先事项:
1. [风险] → [具体行动]
2. [风险] → [具体行动]
3. [风险] → [具体行动]

需监控的预警信号:
□ [早期指标 1]
□ [早期指标 2]
```

## 常见失败类别

| 类别 | 常见原因 |
|----------|---------------|
| **人员** | 关键人员离职、技能缺口、目标不一致、参与度低 |
| **流程** | 时间线过于激进、范围蔓延、依赖问题 |
| **技术** | 无法扩展、集成失败、安全漏洞 |
| **外部** | 市场变化、竞争对手行动、法规变更 |

## 集成
