# 为 Oracle 到 PostgreSQL 迁移创建集成测试

为单个目标项目中的数据访问工件生成集成测试用例。测试验证针对 Oracle 或 PostgreSQL 运行时的行为一致性。

## 先决条件

- 测试项目必须已存在并编译（单独搭建）。
- 在编写测试之前，阅读现有的基础测试类和种子管理器约定。

## 工作流程

```
测试创建：
- [ ] 步骤 1：发现测试项目约定
- [ ] 步骤 2：识别可测试的数据访问工件
- [ ] 步骤 3：创建种子数据
- [ ] 步骤 4：编写测试用例
- [ ] 步骤 5：审查确定性
```

**步骤 1：发现测试项目约定**

阅读基础测试类、种子管理器和项目文件，以了解继承模式、事务管理和种子文件约定。

**步骤 2：识别可测试的数据访问工件**

范围仅限于目标项目。列出与数据库交互的数据访问方法 — 存储库、DAO、存储过程调用器、查询构建器。

**步骤 3：创建种子数据**

- 遵循现有项目的种子文件位置和命名约定。
- 尽可能重用现有种子文件。
- 避免 `TRUNCATE TABLE` — 保持现有数据库数据完整。
- 不要提交种子数据；测试在回滚的事务中运行。
- 确保种子数据不与其他测试冲突。
- 在断言依赖于它之前加载并验证种子数据。

**步骤 4：编写测试用例**

- 从基础测试类继承以获得自动事务创建/回滚。
- 断言逻辑输出（行、列、计数、错误类型），而不是平台特定的消息。
- 断言特定的预期值 — 当种子数据中有具体值可用时，永远不要断言值仅是非空或非空。
- 避免测试不存在的代码路径或断言不可能发生的行为。
- 避免针对同一方法的测试中的冗余断言。

**步骤 5：审查确定性**

针对种子数据重新检查每个非空值断言。确认每个都是确定性的。修复任何依赖于测试控制之外的数据库状态的断言。

## 关键约束

- **Oracle 是黄金标准** — 测试捕获 Oracle 的预期行为。
- **DB 无关断言** — 断言中没有平台特定的错误消息或语法。
- **仅针对 Oracle 进行种子** — 测试项目稍后将迁移到 PostgreSQL。
- **范围限于一个项目** — 不要为超出目标项目的工件创建测试。
