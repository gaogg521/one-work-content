# Create CLI

设计 CLI 表面区域（语法 + 行为），以人为本，对脚本友好。

## 首先执行此操作

- 阅读 `agent-scripts/skills/create-cli/references/cli-guidelines.md` 并将其作为默认标准应用。
- 上游/完整指南：https://clig.dev/ （提议更改：https://github.com/cli-guidelines/cli-guidelines）
- 仅询问锁定界面所需的最少澄清问题。

## 澄清（快速）

询问，如果用户不确定，则使用最佳猜测默认值继续：

- 命令名称 + 一句话目的。
- 主要用户：人类、脚本或两者。
- 输入来源：参数 vs 标准输入；文件 vs URL；密钥（绝不通过标志传递）。
- 输出约定：人类文本、`--json`、`--plain`、退出代码。
- 交互性：允许提示？需要 `--no-input`？破坏性操作需要确认？
- 配置模型：标志/环境/配置文件；优先级；XDG vs 仓库本地。
- 平台/运行时约束：macOS/Linux/Windows；单二进制文件 vs 运行时。

## 可交付成果（输出内容）

设计 CLI 时，生成一个用户可以实现的紧凑规范：

- 命令树 + USAGE 概要。
- 参数/标志表（类型、默认值、必需/可选、示例）。
- 子命令语义（每个做什么；幂等性；状态更改）。
- 输出规则：stdout vs stderr；TTY 检测；`--json`/`--plain`；`--quiet`/`--verbose`。
- 错误 + 退出代码映射（主要故障模式）。
- 安全规则：`--dry-run`、确认、`--force`、`--no-input`。
- 配置/环境规则 + 优先级（标志 > 环境 > 项目配置 > 用户配置 > 系统）。
- Shell 补全方案（如果相关）：安装/可发现性；生成命令或捆绑脚本。
- 5–10 个示例调用（常见流程；包括管道/标准输入示例）。

## 默认约定（除非用户另有说明）

- `-h/--help` 始终显示帮助并忽略其他参数。
- `--version` 将版本打印到 stdout。
- 主要数据到 stdout；诊断/错误到 stderr。
- 添加 `--json` 用于机器输出；考虑 `--plain` 用于稳定的基于行的文本。
- 仅在 stdin 是 TTY 时提示；`--no-input` 禁用提示。
- 破坏性操作：交互式确认 + 非交互式需要 `--force` 或显式 `--confirm=...`。
- 尊重 `NO_COLOR`、`TERM=dumb`；提供 `--no-color`。
- 处理 Ctrl-C：快速退出；有界清理；尽可能做到仅崩溃恢复。
