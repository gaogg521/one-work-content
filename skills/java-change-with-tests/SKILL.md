# java-change-with-tests

## 何时使用
- 任何需要安全合并的 Java 变更（功能/重构/bug 修复）。

## 请求时需要的输入（如果缺失）
- 验收标准（1-3 条要点）。
- 模块名称（如果是多模块仓库）。
- 构建工具和测试约定。
- 该变更是否需要集成测试。

## 步骤
1. 仓库映射（简要）：识别模块、入口点和测试位置。
2. 计划：满足验收标准的最小 diff。
3. 实现：最小化编辑。
4. 测试：
   - 优先使用快速单元测试
   - 仅在需要验证行为时添加集成测试
5. 验证：
   - 运行定向测试
   - 运行 `mvn -q test`（或模块范围的等效命令）
6. 输出 PR 就绪的总结和证据。

## 验证命令（项目特定）
- 使用仓库的构建工具并记录确切的命令和结果。
- 在完整测试套件之前优先使用定向单元测试。

## 输出约定
1) 计划（3-6 步）
2) 变更的文件 + 意图
3) 运行的命令 + 结果
4) 风险 + 后续跟进
